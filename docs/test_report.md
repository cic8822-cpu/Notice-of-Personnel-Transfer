## 2. 코드리뷰 이력
| 회차 | 대상 | 확인된 결함 | 조치 |
|---|---|---|---|
| 1차 | core 7개 모듈 | P1 4건(범용 급 단어 자동확정, 괄호 내용 폐기, 숫자 날짜 오해석 2건) + P2 다수(중첩 표 조사 오교정, 엔티티 처리, 미리보기 인코딩, mimetype 순서, V06 기준 등) | 재현 후 전부 수정, 회귀 테스트 추가 |
| 1차 | 리뷰 재현 중 부정확 | `&amp;#x80;` 사례는 재현되지 않음(이중 이스케이프로 보존) | 단, HTML 방식 해석(`&#x80;`)은 XML 규칙으로 교정 |
| 2차 | 서버·서비스·패키저·배포 | P1 4건(설정 변경 후 결과 잔존, 양식 칸 뒤바뀜 미검출, 학교 선택 잔존, 청결 검사 누락) + P2(부분 반영, Content-Length, 500 응답, MIME 등) | 전부 수정, 회귀 테스트 추가 |
| 2차 | 보안(토큰·Host·Origin·XSS·경로 순회) | 우회 방법 없음 | 변경 없음 |

내가 자체 발견한 결함: 학교명 명부에 괄호가 든 공식명이 있으면 S1 정확일치가 깨지는 문제(리뷰 수정 중 신규 테스트로 발견·수정).

## 4. 수정하지 않은 알려진 한계 (숨기지 않음)
| 항목 | 이유·영향 |
|---|---|
| 학교 접두어를 화면에서 설정할 수 없음 | 자동 감지가 기본이며 `config.json`의 `region_prefix`로 수정. 화면 설정은 후속 |
| 주소창에 세션 토큰이 남음 | 새로고침 유지를 위한 선택. 다른 사람이 화면을 캡처하면 토큰 노출(실행마다 바뀜) |
| 한컴 보안 확인 창 대기 | 변환에 120초 제한을 두었으나 한컴 프로세스가 남을 수 있음. 보안모듈 등록은 한컴 PC에서 확인 필요 |
| V15가 사실상 보조 규칙 | 선행 규칙이 대부분 먼저 걸러냄. 양식 필수 필드는 등록 시점에 강제(종류별 최소 필드) |
| 엑셀 수식 셀의 캐시 값이 없으면 None | 날짜는 값 입력이 일반적이라 영향 낮음, 발령일이 수식이면 확인 필요 |
| 호환 자모(ㅇ 등) NFKC 변환 | 성명에 호환 자모를 입력하는 경우 드묾 |
| 서명되지 않은 exe | 백신 오탐 가능, 보안담당자 해시 확인·예외 등록 필요 |
| 한컴 렌더 정밀 비교 | 자동 검증은 구조·해시 비교. 실제 모양은 사람이 한컴으로 확인 |
| 인원 증가 시 UI 성능 | 표 전체를 한 번에 그림. 수백 건까지만 확인 |

## 5. 결론
자동화로 확인 가능한 범위의 검증은 모두 통과했습니다. 그러나 **인사 업무 완료 기준(계획 12.2의 Phase 7)은 사용자의 실자료·실양식 인수 확인과 서명이 남아 있어 이 보고서만으로 "실사용 준비 완료"라고 할 수 없습니다.** 체크리스트(`docs/체크리스트.md`)의 Phase 7 항목과 부분/미실행 항목을 사용자 PC에서 확인해야 합니다.
