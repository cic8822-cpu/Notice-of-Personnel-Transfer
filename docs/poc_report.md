- 양식의 모든 `{{…}}`는 단일 `<hp:t>` 노드 안에 있었음(분할 0건). 분할 대비 병합 로직은 단위 테스트로 검증.
- 일부 필드는 한컴 메일머지 필드(`fieldBegin`) 내부 → 텍스트만 치환하고 컨트롤은 보존.
- `linesegarray`(줄배치 캐시)는 **그대로 유지**해도 한컴이 열 때 재계산해 1쪽·정상 배치 확인. 제거하지 않음(구조 불변 원칙).
- 한컴 미설치 PC: Track A는 한컴·COM 비의존(표준 라이브러리 zip/re). PDF·HWP 변환 기능만 비활성.

## 한계(숨기지 않음)
1. 확인한 양식은 사용자가 이미 변환해 둔 `.hwpx` 2개입니다. `.hwp`를 앱이 직접 변환하는 경로(`hwp_com.convert_hwp_to_hwpx`)는 코드만 있고 **아직 실행 검증 전**입니다(Phase 3에서 T28 검증).
2. 전보 양식의 원형 직인이 양쪽으로 갈라져 보이는 모양은 **원본 양식에서도 동일**합니다(치환 영향 아님). 원본 HWP 직인과 같은지는 사용자 확인 필요.
3. 한계 길이 값(성명 10자 초과, 학교명 30자 초과)의 줄바꿈 영향은 Phase 3 T23에서 측정.
4. 화면 확인은 60dpi 이미지 육안 비교입니다. 정밀 비교는 구조·해시 검증(6.6-4,5)으로 대체합니다.
